## 2. 專案背景（濃縮）

- 題目：KYS（Know Your Supplier）採購交易風險管控，把事後風險前移到事前，以跨部門「會診」取代各自為政。
- 小組六個部門各派一人：採購處（Evan）、財務處、會計處、國際事務處、稽核處、聯稽。導師：許良維協理。
- 核心構想：**整合知識，不整合系統**。每個部門是自己規則的作者；只分享結論層（規則、紅旗特徵、要問的問題），不分享報告原文。
- 資安定位：目前是**模擬環境**，全部虛構個案，用來證明模式可行；可行後再移到公司內部環境。

## 4. 系統架構（三層）

| 層 | 做什麼 | 期中 | 期末／正式 |
|---|---|---|---|
| 入口層 | 送件、看燈號與會診單 | `index.html`（GitHub Pages） | 公司內部網站 |
| 知識層 | 各部門規則、服務、費率表 | Excel 確認稿 → 轉成網頁資料 | 內部資料庫或核准文件系統 |
| 判斷層 | 依觸發標籤比對規則，給燈號 | 規則比對（可預測、好解釋） | 加 AI 會診（公司核准 AI 平台） |

兩份介面約定是整個平台的關鍵：
- **送件格式**：金額、幣別、是否首次交易、貿易條件、付款條件、是否含勞務、物流資料 → 轉成觸發標籤
- **回覆格式**：每部門回 `[燈號, 一句結論, [建議…]]`

`index.html` 內的主要區塊（以字串搜尋定位）：

| 搜尋字串 | 內容 |
|---|---|
| `const DEPTS=` | 六部門：名稱、地標、服務、示範規則（網頁版，與知識層尚未同步） |
| `const STEPS=` | 劇本一 8 步驟（日本設備個案） |
| `const RATES=` / `function quote` | 國際事務費率表（示範值）與試算 |
| `const IMG=` / `function islandSprite` | 插畫看板；`TOPS` 是每張圖島面頂端的像素位置 |
| `function landmark` / `function extras` | 備援用的程式 3D 模型（工具列「切換 3D 模型」） |
| `const CASES=` | 一鍵會診三個案例：A 三國廠商、B 國內備品、C 日本設備 |
| `function runAuto` | 六部門同步會診動畫與結果彙整 |

## 9. 測試與已知限制

- 網頁在 claude.ai artifact 預覽時，平台會自動隱藏 `[hidden]` 元素；獨立網頁需自己寫 `[hidden]{display:none!important}`（已補上）。曾因此出現白色橫欄。
- 插畫是平面看板，旋轉時永遠面向鏡頭；簡報建議用「全景」＋一鍵會診。
- 公司網路若擋 jsDelivr 或 Google Fonts，3D 畫面不會出現；簡報當天需要離線版（把 three.js 內嵌進檔案）。
- 所有門檻數字（預付 20%、回收 5 年、外幣 NT$1,000 萬、價差 ±20%、追加 10%、關稅 2.5%、匯率 31.60／4.43）都是**示範值**。
